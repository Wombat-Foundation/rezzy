1//! Room version property index.
2//!
3//! Each room version introduces or modifies specific behaviors. This used to
4//! be a list of TODOs proposing a future queryable table -- it wasn't one:
5//! every property below already has a single authoritative implementation
6//! elsewhere in the crate, just not centralized under one name. Building a
7//! second table here would risk exactly the drift bug a single source of
8//! truth per capability is meant to prevent (two answers to "does v11 use
9//! strict redaction rules," one here and one at the real call site, able to
10//! disagree). So this module stays documentation-only: an index pointing at
11//! where each property actually lives, kept accurate rather than aspirational.
12//!
13//! Reference: <https://spec.matrix.org/latest/rooms/>
14
15// Event ID format
16//   - V1-V2: server-assigned (`$localpart:domain`)
17//   - V3:    URL-safe base64 SHA-256 of canonical JSON (reference hash)
18//   - V4+:   same as V3 but with `$` prefix only (no domain)
19// Authoritative: `RoomVersionFormat::uses_reference_hash_event_ids` (v1/v2
20// vs. v3+) in `rezzy_types.rs`; the v3-vs-v4+ base64 padding/charset split
21// is `reconcile::algebraic::EventIdFormat` (`Legacy`/`V3`/`V4Plus`).
22
23// Room ID format
24//   - V1-V11: server-assigned (`!localpart:domain`)
25//   - V12:    derived from the `m.room.create` event's own event ID
26// Authoritative: `RoomVersionFormat::uses_v12_create_rules` gates the
27// derivation; `auth::check_create_room_id` (Rule 1.2) and
28// `auth::check_room_id_matches_accepted_create` (Rule 2, V12+) enforce it.
29// See `docs/spec_audit.md` rows 1.2 and "2 (V12)".
30
31// State resolution algorithm
32//   - V1:  State Resolution v1
33//   - V2+: State Resolution v2 (power events, mainline ordering, auth diff)
34// Authoritative: `StateResVersion::from_room_version` -- the crate's central
35// version-to-algorithm mapping; everything in `resolve/` branches on its
36// output, not on a raw version string/number.
37
38// Creator privileges
39//   - V1-V11: creator is `sender` of `m.room.create` (or legacy `creator` field)
40//   - V12:    creator has infinite power level (i64::MAX), cannot be demoted;
41//             `additional_creators` array in `m.room.create` content is recognized
42// Authoritative: `RoomVersionFormat::uses_v12_create_rules`; the i64::MAX
43// power-level override and `additional_creators` handling live in
44// `auth::user` and the `StateResVersion::V2_1`-and-later branches of
45// `check_auth_with_context`'s power-levels validation (auth/mod.rs).
46
47// Redaction algorithm
48//   - V1-V10: original redaction rules
49//   - V11:    clarified redaction algorithm
50//   - V12:    `m.room.redaction` events are subject to auth rules via
51//             `events` / `events_default` in `m.room.power_levels`
52// Authoritative: `RoomVersionFormat::uses_v11_redaction_rules`;
53// `split_redaction_content`/`redaction_preserved_keys` in `rezzy_types.rs`
54// apply the per-version key tables.
55
56// Knocking
57//   - V1-V6:  not supported
58//   - V7+:    `knock` join rule supported
59// Authoritative: `auth::check_knock_rules` and the `RULE_KNOCK` branch of
60// join-rule validation in `check_auth_with_context`.
61
62// Restricted join rules
63//   - V1-V7:  not supported
64//   - V8+:    `restricted` join rule (join via another room)
65//   - V10+:   `knock_restricted` join rule
66// Authoritative: `auth::room_version_at_least(state, 8 | 10)`, gating the
67// `RULE_RESTRICTED`/`RULE_KNOCK_RESTRICTED` branches directly at their call
68// sites in `check_auth_with_context` and `check_knock_rules`.
69
70// Auth rules changes
71//   - V6: updated authorization rules for events
72//   - V12: `m.room.create` is no longer allowed/required in auth events (V2.1+ state res)
73// Authoritative: `StateResVersion::from_room_version` for the V6 boundary
74// (folded into the `V2` variant); the V12 auth_events change is
75// `StateResVersion::V2_1`-and-later behavior in `resolve/`'s auth-diff and
76// mainline construction.
77
78// Canonical JSON
79//   - V1-V5:  lenient JSON parsing
80//   - V6+:    strict canonical JSON required for hashing and signatures
81// Authoritative: `RoomVersionFormat::requires_strict_canonical_numbers`,
82// enforced by `canonical_redacted_json`'s number-encoding path
83// (`CanonicalizationError`) in `rezzy_types.rs`.
