15//! Extensible homomorphic accumulation via `LtHash`.
16//!
17//! `LtHash` (Lattice Hash) is based on the homomorphic hashing paradigm first
18//! introduced by Bellare and Micciancio in their 1997 paper *"A New Paradigm
19//! for Collision-Free Hashing: Incrementality at Reduced Cost"*. This specific
20//! instantiation (by default 2048 bytes, using 1024 16-bit integers and
21//! wrapping addition) is modeled after the industry-standard implementation in
22//! Meta's Folly library (`folly::crypto::LtHash`).
23//!
24//! Each element is expanded to `2 * LANES` bytes with the BLAKE3 extendable
25//! output function (XOF), unpacked into `LANES` little-endian 16-bit lanes.
26//! The accumulator is the wrapping addition of those vectors, and the wire
27//! digest is `BLAKE3(lattice)`. This provides:
28//!
29//! - **O(1) incremental updates**: insert = `hash + expanded`,
30//!   remove = `hash - expanded`.
31//! - **Order independence**: addition is commutative + associative.
32//! - **Cryptographic security**: hard to find set collisions (SVP).
33//!
34//! # Why BLAKE3 instead of SHAKE256
35//!
36//! The original draft expanded elements with SHAKE256 (FIPS 202). Squeezing
37//! 2048 bytes costs 16 `Keccak-f1600` permutations, and no mainstream CPU has
38//! a Keccak instruction, so expansion dominated every insert. BLAKE3 replaces
39//! it with an ARX construction that maps to the same SIMD paths on every
40//! target (AVX2/AVX-512 on x86, NEON on ARM, `simd128` on wasm) and is
41//! constant-time by construction.
42//!
43//! The win is real but it is a constant factor, not an order of magnitude: on a
44//! 3.6 GHz Skylake-derived core this module squeezes 2048 bytes in roughly
45//! 1.8 us against roughly 5.5 us for the SHAKE256 path it replaces, so expect
46//! single-digit microseconds per seed rather than nanoseconds. Reproduce with
47//! `cargo bench --manifest-path benches/Cargo.toml -- lthash_comprehensive`,
48//! whose expansion section measures the XOF and the collapse separately, or
49//! with `cargo bench --manifest-path benches/Cargo.toml --bench rezzy -- lthash_backends`, which times this stack head to head against the
50//! retired SHAKE256 + `BLAKE2b` one after checking it against the published
51//! MSC4500 vectors.
52//!
53//! Note that the pinned `blake3` dependency keeps `default-features = false`,
54//! so expansion uses the portable backend. Enabling blake3's `std` feature
55//! turns on runtime SIMD detection; the digest is fixed by the BLAKE3 spec, so
56//! both backends agree byte for byte, and it was not measurably faster for the
57//! XOF path when measured here.
58//!
59//! The domain-separation tags are versioned `...:blake3:v1` so a digest
60//! produced by this module can never be confused with a SHAKE256
61//! instantiation of the same shape.
62//!
63//! # Layout
64//!
65//! - `lattice` holds [`LtLattice`], [`LtHash`], the arithmetic traits and
66//!   serialization.
67//! - `encoding` holds the BLAKE3 expansion and seed encodings.
68//!
69//! This module has no dependency on room state. The MSC4500 domain layers
70//! (`RedactionOverlay`, `ResolutionInputs`, `PduLtHash`) and `from_state`
71//! live in [`crate::state::lthash`].
